Проведён комплексный аудит бэкенда (`api/game.js`), фронтенда (`public/index.html`), конфигурации и архитектуры. Ниже структурированный отчёт по категориям.

## 1. КРИТИЧЕСКИЕ БАГИ И ЛОГИЧЕСКИЕ ОШИБКИ

### 1.1 **BUG-01: Некорректный расчёт аренды для коммунальных предприятий при нескольких владельцах**

**Файл:** `api/game.js`, функция `calculateRent()`

**Строка:** ~270

**Описание:**
```javascript
if (cell.type === 'utility') {
  const ownerUtils = Object.entries(room.properties)
    .filter(([id, p]) => p.ownerId === prop.ownerId && BOARD[parseInt(id)].type === 'utility')
    .length;
  return diceSum * (ownerUtils >= 2 ? 10 : 4);
}
```

**Проблема:** Код считает коммунальные предприятия только по владельцу имущества (`prop.ownerId`), но не учитывает ситуацию, когда коммунальные предприятия находятся в совместном договоре о монополии (`monopolyDeal`). Согласно правилам, договор охватывает только цветовые группы улиц, а коммунальные предприятия не входят ни в какую цветовую группу. Однако логика консистентна — это не баг, но может быть источником путаницы.

**На самом деле**, проблема глубже: если два игрока в договоре о монополии владеют разными коммунальными предприятиями, система будет считать каждое отдельно (множитель 1), вместо того чтобы объединить. Но учитывая определение договора ("на одну цветовую группу"), это скорее недостаток правил, а не баг кода.

**Статус:** Низкий приоритет, но требует уточнения игровых правил.

### 1.2 **BUG-02: Аукцион может "зависнуть" при переходе между игроками**

**Файл:** `api/game.js`, функция `checkAuctionExpiry()`

**Строка:** ~390

**Описание:**
```javascript
function checkAuctionExpiry(room) {
  if (room.turnPhase !== 'auction' || !room.auction) return false;
  const elapsed = Date.now() - room.auction.lastBidTime;
  if (elapsed >= room.auction.timerDuration) {
    // ... завершение аукциона
    room.turnPhase = 'endturn';
    room.lastUpdate = Date.now();
    return true;
  }
  return false;
}
```

**Проблема:** Функция вызывается только:
- При `GET /api/state` (поллинг)
- При `GET /api/auction_check` (специальный опрос таймера)

Если игрок закрыл приложение или сетевое соединение разорвалось, аукцион может зависнуть в состоянии `'auction'` на сервере, а при попытке другого игрока совершить ход получится ошибка типа "Cannot end turn while auction active" или зависание.

**Решение:** Добавить проверку `checkAuctionExpiry()` в начало каждого POST-обработчика (roll, buy и т.д.) перед основной логикой.

### 1.6 **BUG-06: Игрок может объявить банкротство, даже если может погасить долг**

**Файл:** `api/game.js`, маршрут `bankrupt`

**Строка:** ~1287

**Описание:**

**Проблема:** Проверка на восстановление уже добавлена (отмечена `// BUG-06 fix`), но это означает, что баг был когда-то. Важно убедиться, что функция `canPlayerRecoverServer()` работает корректно.

**Функция:**
```javascript

  let potential = player.balance;
  Object.entries(room.properties).forEach(([cellId, prop]) => {
    if (prop.ownerId === player.id) {
      if (prop.houses > 0) {
        const cell = BOARD[parseInt(cellId)];
        potential += prop.houses * Math.floor(cell.houseCost / 2);
      }
      if (!prop.mortgaged) {
```

- Баланс: **–100**
- Улица на 60 (не заложена): можно заложить и получить 30
- Общее: –100 + 30 = –70 (всё ещё минус, но улица заложена)
- Вторая улица на 80: +40
- Итог: –70 + 40 = –30... нужна третья

Логика кажется правильной, но сложна для ручной проверки. **Рекомендация:** добавить unit-тесты.

**Статус:** Исправлено, но требует тестирования.

### 1.8 **BUG-08: Распределение аренды в договоре монополии некорректно**

**Файл:** `api/game.js`, функция `distributeRent()`

**Строка:** ~300

**Описание:**
```javascript
function distributeRent(room, cellId, rentAmount, payerId) {
  const deal = getMonopolyDealForCell(room, cellId);
  const prop = room.properties[cellId];

  // BUG-08 fix: Only distribute through deal if the owner is a member of the deal
  if (deal && !deal.members.includes(payerId) && deal.members.includes(prop.ownerId)) {
    if (deal.splitType === 'equal') {
      const share = Math.floor(rentAmount / deal.members.length);
      const remainder = rentAmount - share * deal.members.length;
      deal.members.forEach((memberId, i) => {
        const player = getPlayerById(room, memberId);
        if (player) player.balance += share + (i === 0 ? remainder : 0);
      });
    } else {
      // ... по вложениям
    }
  } else {
    // Normal: all goes to owner
    const owner = getPlayerById(room, prop.ownerId);
    if (owner) owner.balance += rentAmount;
  }
}
```

**Проблема:** Условие `!deal.members.includes(payerId) && deal.members.includes(prop.ownerId)` проверяет, что плательщик НЕ в договоре, но владелец В договоре. Это означает:

1. Если плательщик **в** договоре, аренда идёт только владельцу (условие ложь, идёт в else). ✓ Верно.
2. Если плательщик **не в** договоре, а владелец **в** договоре, аренда делится. ✓ Верно.
3. Если плательщик **не в** договоре, а владелец **не в** договоре — идёт в else (аренда владельцу). ✓ Верно.

Код выглядит корректным, но логика запутана. **Рекомендация:** рефакторить для читаемости с явными комментариями.

**Статус:** Код верен, но требует уточнения в комментариях.

### 1.12 **BUG-12: Не учитываются монопольные договоры при проверке полной группы**

**Файл:** `api/game.js`, функция `hasFullGroup()`

**Строка:** ~258

**Описание:**
```javascript
function hasFullGroup(room, color, playerId) {
  const group = COLOR_GROUPS[color];

    const p = room.properties[cid];
    if (!p) return false;
    if (p.ownerId === playerId) return true;
```

На самом деле, логика верна: `deal.members.includes(playerId) && deal.members.includes(p.ownerId)` проверяет, что оба (игрок и владелец) в одном договоре, что гарантирует, что все улицы группы в договоре.

**Статус:** Код верен, требует уточнения в комментариях.

### 1.14 **BUG-14: Неправильный расчёт остаточной стоимости при переводе имущества**

**Файл:** `api/game.js`, функция `calculateResidualValue()` и маршрут `monopoly_exit`

**Строка:** ~497

**Описание:**
```javascript
function calculateResidualValue(room, playerId) {
  let value = 0;
  Object.entries(room.properties).forEach(([cellId, prop]) => {
    if (prop.ownerId === playerId) {
      const cell = BOARD[parseInt(cellId)];
      if (prop.mortgaged) {
        // Buyer must pay unmortgage cost
        value += Math.floor(cell.price / 2 * 1.1);
      } else {
        value += Math.floor(cell.price / 2);
      }
      if (prop.houses > 0) {
        value += prop.houses * Math.floor(cell.houseCost / 2);
      }
    }
  });
  return value;
}
```

**Проблема:** Для заложенного имущества рассчитывается стоимость выкупа (половина + 10%), но это не совсем верно. Согласно классическим правилам:
- Заложить: получить половину цены.
- Выкупить: заплатить половину + 10%.

Если имущество уже заложено, новый владелец может либо держать его в залоге (получает 50% оценки), либо выкупить (платит 55%). Текущая функция предполагает, что он выкупит сразу. Это может быть преувеличением.

**Правильный подход:**
```javascript
if (prop.mortgaged) {
  // Mortgage value remains: the buyer buys the right to own (can unmortgage later)
  value += Math.floor(cell.price / 2);
}
```

Но это зависит от игровых правил. Если говорить о переводе при выходе из договора, логично предположить, что новый владелец получает активы в полном состоянии, т.е. должен платить за выкуп из залога.

**Статус:** Требует уточнения правил.

### 1.15 **BUG-15: Гонка при одновременном завершении аукциона**

**Файл:** `api/game.js`, маршруты `auction_bid` и `auction_check`

**Строка:** ~1161–1190

**Описание:** Если два клиента одновременно отправляют ставку и поллят статус аукциона, может возникнуть race condition:
1. Клиент A проверяет `if (elapsed >= room.auction.timerDuration)` — ложь, продолжает.
2. Клиент B в то же время завершает аукцион и устанавливает `room.auction = null`.
3. Клиент A пытается обновить `room.auction.currentBidderId` — crash (потому что null).

**Решение:** Использовать мьютексы или CAS операции Redis (если перейти на Redis). Временное решение:

```javascript
case 'auction_bid': {
  // ...
  if (!room.auction) return res.status(400).json({ error: 'Auction not active' });
  const expired = checkAuctionExpiry(room);
  if (expired) return res.status(400).json({ error: 'Auction already expired' });
  // ... остаток логики
}
```

**Статус:** **КРИТИЧНЫЙ** для многопользовательской игры. Требует рефакторинга.

### 1.16 **BUG-16: Банкротный аукцион не завершается, если очередь пуста**

**Файл:** `api/game.js`, маршрут `bankrupt`, функция `startNextBankruptAuction()`

**Строка:** ~430

**Описание:**
```javascript
function startNextBankruptAuction(room) {
  if (!room.bankruptAuctionQueue || room.bankruptAuctionQueue.length === 0) {
    room.bankruptAuctionQueue = null;
    room.turnPhase = 'endturn';
    return;
  }
  // ...
}
```

**Проблема:** Если все имущество банкрота было продано на аукционах, очередь опустеет, и `turnPhase` станет `'endturn'`. Однако не проверяется, должна ли игра закончиться (если остался только один игрок). Это может привести к тому, что игра продолжится с мёртвым игроком.

**Решение:** После завершения очереди проверить условие победы:

```javascript
function startNextBankruptAuction(room) {
  if (!room.bankruptAuctionQueue || room.bankruptAuctionQueue.length === 0) {
    room.bankruptAuctionQueue = null;
    const active = getActivePlayers(room);
    if (active.length <= 1) {
      room.state = 'finished';
      room.winner = active[0]?.id;
```

### 2.2 **SEC-02: CSRF-защита отсутствует**

**Файл:** `api/game.js`

**Строка:** Все POST-маршруты

**Описание:** API не использует CSRF-токены. Однако, поскольку это Telegram Mini App, запросы идут с заголовком `X-Telegram-Init-Data`, который подписан. Если `initData` валидна, запрос от легального клиента.

**Рекомендация:** CORS хорошо настроен (только Telegram), но для дополнительной защиты можно добавить CSRF-токены в сессию.

**Статус:** **СРЕДНИЙ приоритет**. Текущая защита достаточна, но можно улучшить.

### 3.3 **ARCH-03: Race condition при одновременном поллинге и действии**

**Файл:** `public/index.html`

**Описание:** Если игрок выполняет действие (roll) в то время, как идёт поллинг (state), может возникнуть конфликт:
1. Поллинг получает старое состояние.
2. Запрос действия изменяет состояние на сервере.
3. Поллинг обновляет UI неправильным состоянием.

Это автоматически разрешается `lastUpdate` версионированием, но может быть лучше.

**Решение:** Использовать `actionLock` для блокировки поллинга во время действия.

**Проверим код:**
```javascript
async function safeApiCall(endpoint, body) {
  if (actionLock) return null;
  actionLock = true;
  try {
    const result = await apiCall(endpoint, body);
    return result;
  } finally {
    actionLock = false;
  }
}
```

`actionLock` используется для блокировки кнопок, но поллинг не блокируется. Можно добавить:

```javascript
pollInterval = setInterval(async () => {
  if (!roomId || actionLock) return; // ← Пропустить, если идёт действие
  // ...
}, 2500);
```

**Статус:** **СРЕДНИЙ приоритет**. Текущая система работает через версионирование, но можно улучшить.

### 3.4 **ARCH-04: Отсутствие обработки сетевых ошибок**

**Файл:** `public/index.html`, функции `apiCall()`, `apiGet()`

**Описание:**
```javascript
async function apiCall(endpoint, body) {
  const headers = { 'Content-Type': 'application/json' };
  if (initData) {
    headers['X-Telegram-Init-Data'] = initData;
  }
  const res = await fetch(`${API}/${endpoint}`, {
    method: 'POST',
    headers,
    body: JSON.stringify({ ...body, playerId: userId, playerName: userName }),
  });
  return await res.json();
}
```

**Проблема:** Нет обработки ошибок fetch (например, сетевые таймауты, 500 ошибки). Если сервер недоступен, клиент повиснет.

**Решение:**

```javascript
async function apiCall(endpoint, body) {
  try {
    const res = await fetch(`${API}/${endpoint}`, {
      method: 'POST',
      headers,
      body: JSON.stringify({ ...body, playerId: userId, playerName: userName }),
      timeout: 5000, // Таймаут 5 сек
    });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (err) {
    console.error(`API error: ${err.message}`);
    return { success: false, error: 'Network error. Try again.' };
  }
}
```

**Статус:** **ВЫСОКИЙ приоритет**.

```javascript
if (clientLastUpdate && clientLastUpdate >= room.lastUpdate && !auctionCompleted) {
  return res.json({ success: true, notModified: true });
}
// Отправить только изменённые поля
const delta = {
  players: room.players.map(p => ({ id: p.id, balance: p.balance, position: p.position, ... })),
  properties: room.properties,
  currentPlayerIndex: room.currentPlayerIndex,
  turnPhase: room.turnPhase,
  notifications: room.notifications.slice(-5), // Только последние
  // ...
};
return res.json({ success: true, delta });
```

**Статус:** **СРЕДНИЙ приоритет** для масштабирования.

### 6.3 **GAME-03: Отсутствует правило о равномерной застройке в договоре**

**Файл:** `api/game.js`, функция `build()`

**Строка:** ~1069

**Описание:** При совместной монополии должны соблюдаться классические правила Монополии о равномерной застройке. Текущий код проверяет это, но не для всех участников договора.

Логика кажется правильной, но может быть запутана при большом количестве участников. Рекомендуется добавить комментарии.

**Статус:** **НИЗКИЙ приоритет**, логика верна, но требует уточнения.

### 8.4 **REFACTOR-04: Добавить явное состояние для аукционов**

**Текущее состояние:** `turnPhase === 'auction'` и `room.auction !== null`.

**Предложение:** Создать отдельный класс `Auction`:

```javascript
class Auction {
  constructor(cellId, initiatorId, timerDuration) {
    this.cellId = cellId;
    this.currentBid = 0;
    this.currentBidderId = null;
    this.initiatorId = initiatorId;
    this.lastBidTime = Date.now();
    this.timerDuration = timerDuration;
  }

  isExpired() {
    return Date.now() - this.lastBidTime >= this.timerDuration;
  }

  placeBid(playerId, amount) {
    if (amount <= this.currentBid) throw new Error('Bid too low');
    this.currentBid = amount;
    this.currentBidderId = playerId;
    this.lastBidTime = Date.now();
  }
}
```

**Статус:** **ЖЕЛАТЕЛЬНО**, улучшит структуру.

```javascript
async function apiCall(endpoint, body) {
  const headers = { 'Content-Type': 'application/json' };
  if (initData) {
    headers['X-Telegram-Init-Data'] = initData;
  }
  
  try {
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), 5000); // 5 сек таймаут
    
    const res = await fetch(`${API}/${endpoint}`, {
      method: 'POST',
      headers,
      body: JSON.stringify({ ...body, playerId: userId, playerName: userName }),
      signal: controller.signal,
    });
    
    clearTimeout(timeoutId);
    
    if (!res.ok) {
      console.error(`API error: HTTP ${res.status}`);
      return { success: false, error: `Ошибка сервера (${res.status})` };
    }
    
    return await res.json();
  } catch (err) {
    console.error(`API error: ${err.message}`);
    if (err.name === 'AbortError') {
      return { success: false, error: 'Таймаут подключения' };
    }
    return { success: false, error: 'Ошибка сети. Попробуйте позже.' };
  }
}
```
